# OSINT 情报搜集流程

用户提出「搜集 / 收集 / 搜索 / 查找 / 调查 / 调研 / 查一下 / 情报 / 线索」类需求时，按本流程执行。

## 0. 先确认边界（必做）

- 只处理**公开信息**：不获取未授权凭据、隐私数据、非公开内容
- 不针对真实个人实施操纵、冒充、诱骗
- 请求越界时明确说明，并给出合法合规范围内的替代帮助

## 1. 界定目标与问题

先用一句话写清三件事：**调查对象**（人 / 组织 / 域名 / IP / 账号 / 事件）+ **想知道什么** + **时间范围**。
用户表述模糊时按最可能的解释推进，并在产出中显式说明所做的假设。

## 2. 时间锚定（必做）

调用 `run_powershell` 执行 `Get-Date` 获取当前日期，并把它写进检索词。
**不要把年份写死在记忆里**（"最新"要落到真实年月）。

## 3. 本地权威源优先

若涉及情报画板 / 图谱：

1. `graphrag_status` 检查画板是否已保存
2. 已保存 → `graphrag_query(keyword)`（本地权威数据，**优先于联网搜索**）
3. 未保存 → 提示用户在 CANVAS 标签保存后再查，同时继续用联网检索

> 不要让画板里已有的实体重复做联网搜索（浪费迭代）。

## 4. 多源检索（至少两个独立来源）

- `ddg_search(query)`：主检索（中文一轮 + 英文一轮）
- `web_search(query)`：备用/交叉检索
- 关键词构造：2-5 个词，避免整句；加限定词（官方 / 新闻 / 报告 / 演讲 / 简历）
- 高级检索语法（`site:`、`filetype:`、`intitle:`、精确短语、排除词）见
  `references/search-operators.md`——需要精确定位时**读取该文件**

## 5. 正文采集与溯源

- `web_fetch(url)` 或 `ddg_fetch_content(url)`：抓取页面正文再判断，别只信搜索摘要
- `ddg_expand_link(url)`：先还原短链/跳转链接，确认真实域名再采信
- ⚠️ `web_fetch` 默认**遵守目标站点 robots.txt**；被禁止时会拒绝并说明原因——如实告知用户，改用其他公开来源，不要伪造内容

每条信息都要记录：**标题 / 链接 / 采集时间 / 来源类型（一手 / 二手 / 推测）**。

## 6. 落盘与结构化（便于复核与复用）

- 目录建议：`data/osint/<主题>-<YYYYMMDD>/`
- `sources.md` 存原始来源清单；`report.md` 存结构化结论
- 用 `write_file` 新建；后续补充用 `edit_file` 增量修改，**不要整文件覆盖**
- 步骤较多时用 `read_todo` / `update_todo` 维护任务清单

## 7. 产出规范

```
1. 结论摘要：关键判断 + 置信度（高 / 中 / 低）
2. 依据与细节：事实、时间线、实体关系（可用表格）
3. 来源与时间：逐条列出链接与采集时间
4. 不确定性与下一步：信息缺口、来源冲突、建议的核查方向
```

## 8. 产出前红线自查

- [ ] 全部来自**公开来源**，且标注了出处与采集时间？
- [ ] 至少两个独立来源交叉验证？（单源结论必须标注「未经证实」）
- [ ] 明确区分了**事实 / 推断 / 假设**？
- [ ] 时间使用**真实当前日期**（已 `Get-Date`）？
- [ ] 没有编造任何链接、数据或结论？

## 附：持续跟踪

需要长期盯着某个来源时，用 `fetch_rss_feed(url)` 拉取最新文章，
或提示用户在右侧 RSS 面板订阅，由后台定时抓取并推送。
